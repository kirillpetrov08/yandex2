# Исправления 1.0.1 — падения и оформление

Сборка: `versionCode 2` / `versionName "1.0.1"` (подняты в `app/build.gradle.kts`).
Всё ниже исправлено по скриншотам и описанию ошибок с реального устройства.

## 1. Падение при «Фото → PDF»

Причина — освобождение битмапов до записи файла. `ImagesToPdf.convert` делал
`bitmap.recycle()` сразу после `finishPage`, но `PdfDocument` не растеризует страницы
в этот момент: картинки нужны ему на шаге `document.writeTo(stream)`. К моменту записи
Skia обращалась к уже освобождённой памяти, и процесс падал нативно — без Kotlin-стека,
с системным диалогом «произошла ошибка».

Что сделано:

- битмапы страниц живут до конца записи и освобождаются в `finally` после `writeTo`;
- разрешение декодирования ограничивается по числу файлов (`decodeSide`):
  до 2600 px на 1–2 файла, 2000 / 1600 / 1200 px при большем количестве
  (для страниц «по размеру фото» — не больше 1600 px, больше всё равно не видно);
- белая подложка рисуется всегда, а не только на A4, — прозрачные PNG больше не дают серый фон;
- при ошибке записи неполный файл удаляется, а не остаётся в кэше;
- `android:largeHeap="true"` — на слабых устройствах запас памяти для фото и PDF;
- в `ImageConverter` декодирование всегда идёт в `ARGB_8888`, а `ImageDecoder` (HEIC/AVIF)
  принудительно просит `ALLOCATOR_SOFTWARE`: иначе декодер может вернуть HARDWARE-битмап,
  который нельзя ни рисовать на обычном canvas, ни копировать.

## 2. Падение при входе в «Историю»

Причина — одинаковые ключи в `LazyColumn`: `key = { _, entry -> entry.id }` падает
(`IllegalArgumentException`), если в истории есть две записи с одним id. Дубли появлялись,
потому что id запроса не обновлялся при повторной конвертации тех же файлов, а также могли
появиться после перезапуска работы WorkManager'ом (процесс убит — работа повторяется с тем же id).

Что сделано:

- новый `requestId` на **каждый** запуск конвертации (`ToolViewModel.enqueue`);
- `HistoryTsv.dedupe` — повторы по id убираются при чтении файла истории и при записи;
- `HistoryStore.addAll` работает как upsert: запись с тем же id заменяется, а не добавляется;
- `HistoryViewModel.publish` дополнительно страхует список перед показом.

Уже испорченная история на устройстве лечится сама: дубликаты отбрасываются при чтении,
данные стирать не нужно.

## 3. Склеенный текст «Было2,2 МБ», «Стало981 Б», «Экономия100 %»

`StatRow` — `Row` с `Arrangement.SpaceBetween` без `fillMaxWidth()`: Row сжимался по содержимому
и подпись слипалась со значением. Теперь строка занимает всю ширину, подпись с `weight(1f)`,
значение прижато вправо, между ними 12 dp.

Дополнительно в карточке результата:

- «Экономия 100 %» больше не показывается: файл нулевого размера невозможен, пишем «>99 %»;
- если файл вырос (например, JPG → PNG), вместо «Экономия −435 %» выводится
  «Файл стал больше — на 435 %», без акцентного цвета.

## 4. «Вертикальные буквы» в чипах

`OptionRow` в настройках и чипы качества в инструменте стояли в `Row` без переноса: третий
вариант («Минимальный размер») сжимался до ширины одной буквы. Все ряды чипов переведены на
`FlowRow` (`SelectableChipRow` / `SingleChoiceChipRow` в `ui/components/FormatChips.kt`) —
варианты переносятся целиком, ничего не обрезается. То же для фильтров формата в истории,
кнопок «Из галереи / Из файлов» и списка страниц PDF.

## 5. Пустой предпросмотр в шторке «Готово!»

Раньше в шторку жёстко передавался `ToolKind.IMAGES`, поэтому для TXT и PDF рисовалась пустая
тёмная рамка. Теперь `FilePreview` определяет тип по расширению файла: миниатюра картинки,
первая страница PDF, первый кадр видео, начало текста для TXT, карточка со значком и размером
для аудио. В шторке добавлены имя и размер файла, а сама шторка получила прокрутку — нижние
кнопки больше не обрезаются на невысоких экранах.

## 6. Отступы и оформление

Введён единый шаг отступов `AppDimens` (4 / 8 / 12 / 16 / 24 dp, `BlockGap` 20 dp,
`CardPadding` 16 dp, `RowPadding` 12 dp, `StatGap` 6 dp) и он применён на всех экранах:
главная, инструмент, шторка результата, история, настройки. Заголовки секций получили
одинаковый отступ до содержимого, строки в настройках — одинаковые поля и `weight` для текста,
кнопки — высоту не меньше 48 dp.
