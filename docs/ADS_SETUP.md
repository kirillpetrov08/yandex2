# Реклама РСЯ: блоки, ID и сборка APK — пошагово

> Файл дополняет `docs/APK_RELEASE.md` (общий порядок релиза) и `docs/RUSTORE_DEPLOY.md`
> (публикация в магазине). Здесь только про рекламу: **какие блоки нужны**, **что вписать
> в код**, **как собрать APK**, чтобы после модерации показы сразу приносили доход.
>
> Терминология: «Конвертер+» — **не игра**. В RuStore тип приложения — неигровое,
> категория **«Полезные инструменты»**. На блоки РСЯ это не влияет: они создаются одинаково
> и для игр, и для утилит.

---

## 0. Что уже сделано и что осталось вам

**Реклама в проекте настроена на ваши реальные блоки — ничего вписывать в код не нужно.**

Уже сделано:

| Что | Где | Значение |
|---|---|---|
| Тестовый режим выключен | `gradle.properties` | `ads.testMode=false` |
| Баннер | `gradle.properties` | `ads.bannerUnitId=R-M-20230616-2` |
| Межстраничная | `gradle.properties` | `ads.interstitialUnitId=R-M-20230616-4` |
| Rewarded | `gradle.properties` | `ads.rewardedUnitId=R-M-20230616-7` |
| Защита от демо-блоков в релизе | `app/build.gradle.kts` | сборка падает, если ID не вида `R-M-XXXXXXX-Y` |
| Три формата рекламы в коде | `ads/`, `ui/` | баннер, межстраничная, rewarded |

Осталось вам (по порядку):

1. Собрать релизный APK (раздел 4).
2. Загрузить APK в RuStore и пройти модерацию (`docs/RUSTORE_DEPLOY.md`).
3. Скопировать ссылку на карточку RuStore и добавить её в карточку приложения в РСЯ (раздел 6).
4. Дождаться статуса **Активно** — с этого момента показы тарифицируются.

Пока пункт 4 не выполнен, на ваших ID РСЯ сама показывает **тестовые креативы**: реклама
видна, логи чистые, дохода нет. Это нормально и не ошибка.

## 1. Ваши три блока в кабинете РСЯ

В кабинете РСЯ (приложение «конвертатор», `PAGE_ID = 20230616`) уже созданы три блока —
их ID и стоят в проекте:

| № | Формат в кабинете | ID блока | Куда вписан | Где показывается в приложении |
|---|---|---|---|---|
| 1 | **Баннер** | `R-M-20230616-2` | `ads.bannerUnitId` | низ главной и истории, низ экрана инструмента |
| 2 | **Межстраничная реклама** | `R-M-20230616-4` | `ads.interstitialUnitId` | после закрытия шторки с результатом |
| 3 | **Реклама с вознаграждением** | `R-M-20230616-7` | `ads.rewardedUnitId` | по кнопкам: убрать водяной знак, большой файл, точное OCR, «Убрать рекламу на 30 минут» |

Стратегия CPM у всех трёх — **«Максимальный доход»**, статус **«Активно»**.

Больше блоков не нужно. Нативные, App Open, «Лента», InStream **не создавать**: в проекте
они не интегрированы, а ТЗ запрещает App Open и нативные форматы.

### 1.1 Если понадобится создать блок (новый формат, второе приложение)

Поля кабинета и порядок действий:

1. Открыть <https://partner.yandex.ru> → раздел **«Реклама в приложениях»** → **«Приложения»**.
2. Если приложения в кабинете нет: **«Добавить приложение»** → платформа Android → пакет
   `com.converterplus.app` → вариант «приложение ещё не опубликовано» (ссылку на RuStore
   добавите позже, раздел 6).
3. Напротив приложения нажать **«Добавить»** (или на странице приложения — **«Добавить блок»**).
4. **Формат рекламы** — один из трёх: «Баннер», «Межстраничная реклама»,
   «Реклама с вознаграждением».
5. **Название блока** — например `Конвертер+ / баннер / низ экрана`. По названию потом
   понятно, где блок стоит.
6. **CPM стратегия** — «Максимальный доход» (для старта ничего не ограничивает) либо
   «Порог eCPM» + значение и валюта (отсекает дешёвые показы).
7. **Добавить рекламную сеть / Adfox** — не подключать на первом релизе.
8. Для rewarded РСЯ дополнительно спросит **валюту и сумму вознаграждения за первый полный
   просмотр**. Внутриигровой валюты у нас нет — пишите, например, `бонус` и `1`.
   На код это не влияет: что именно дать пользователю, решает приложение.
9. Вкладка **География** — можно пропустить.
10. **Сохранить**. В списке появится блок с ID `R-M-<PAGE_ID>-<номер>` — скопируйте его
    в `gradle.properties` (раздел 3.1).

ID устроен так: `R-M` (продукт) + `PAGE_ID` (номер вашего приложения) + номер блока.
В одном приложении допустимо до 200 активных блоков.

### 1.2 Особенности форматов

**Баннер (блок № 1).** Формат в кабинете называется «Баннер», вид (адаптивный sticky)
определяет приложение. В проекте — адаптивный sticky: ширина равна ширине экрана,
высота контейнера фиксирована (50 dp), поэтому интерфейс не дёргается при загрузке креатива.

- Видео внутри баннера показывается только при размере блока от **300×60** dp
  (или 160×300 dp для узкого вертикального). Не нужен видеокреатив в баннере — отключите
  его в настройках блока.
- Ширина баннера в приложении ограничена диапазоном 280–720 dp: уже 280 dp креатив обрезается.

**Межстраничная (блок № 2).** Полноэкранная реклама в паузе между действиями.
В проекте показывается строго после закрытия шторки с результатом, не раньше **3-й**
конвертации и не чаще одного раза в **120 секунд**. Никогда: при запуске, во время
конвертации, в онбординге, в настройках, на самой шторке результата.

**Реклама с вознаграждением (блок № 3).** Награда выдаётся **только** в колбэке
`onAdRewarded()`. Комбинаторная реклама = 30 секунд просмотра, видео = до конца ролика.
Закрыл раньше — награды нет, приложение пишет «Ролик закрыт раньше времени — награда не выдана».

## 2. Где в приложении стоит каждый блок

| Блок | Файл | Что делает |
|---|---|---|
| Баннер | `ui/navigation/AppNavigation.kt` | снизу на главной и в истории; в онбординге и настройках — **нет** |
| Баннер | `ui/screens/tool/ToolScreen.kt` | снизу на экране инструмента, с отступом от кнопки «Конвертировать» |
| Баннер (виджет) | `ads/BannerSlot.kt` | контейнер фиксированной высоты, без кнопок поверх креатива |
| Межстраничная | `ui/screens/tool/ToolScreen.kt` (`maybeShowInterstitial`) | вызывается после закрытия шторки результата |
| Межстраничная (правила) | `ads/AdPolicy.kt` | «каждая 3-я конвертация», «не чаще 120 с», режим «без рекламы» |
| Rewarded | `ui/screens/tool/ToolScreen.kt` | три точки входа: снять водяной знак, подтвердить большой файл, точное OCR |
| Rewarded | `ui/screens/removeads/RemoveAdsScreen.kt` | четвёртая: «Убрать рекламу на 30 минут» из настроек |
| Rewarded (выдача награды) | `ui/screens/tool/ToolViewModel.kt` (`onRewardedGranted`) | награда применяется только после `onAdRewarded()` |
| Счётчик конвертаций | `work/ConversionWorker.kt` | считает конвертации для правил межстраничной |

Реклама нигде не перекрывает кнопки: баннер живёт в отдельном контейнере, отступ от
интерактивных элементов — `AppDimens.BannerSafeGap` = 16 dp (требование РСЯ — не менее 12 dp).
Слот полностью скрывается, если не получено согласие или активен режим «без рекламы».

## 3. Что и куда вписано: фактическое состояние файлов

### 3.1 `gradle.properties` (корень проекта) — главное место

Сейчас в файле ровно это:

```properties
# --- Реклама Яндекс РСЯ ---
ads.testMode=false
ads.bannerUnitId=R-M-20230616-2
ads.interstitialUnitId=R-M-20230616-4
ads.rewardedUnitId=R-M-20230616-7
ads.interstitialEveryNthConversion=3
ads.interstitialMinIntervalSeconds=120
ads.rewardedNoAdsMinutes=30
```

Как это работает:

- значения из `gradle.properties` попадают в `BuildConfig` (`ADS_TEST_MODE`,
  `ADS_BANNER_UNIT_ID`, …) — см. `app/build.gradle.kts`;
- `ads.testMode=false` включает боевые ID: показываются креативы, за которые начисляется доход;
- форматы ID проверяются шаблоном `^R-M-\d{4,}-\d{1,3}$` (`ads/AdUnits.kt`), а при
  `ads.testMode=false` сборка **падает** с сообщением:

```
ads.testMode=false, но ID блоков не похожи на реальные (нужен вид R-M-XXXXXXX-Y):
ads.bannerUnitId=demo-banner-yandex. Возьмите ID из кабинета РСЯ:
partner.yandex.ru → Реклама в приложениях → Приложения.
```

Это защита от самой дорогой ошибки — релиза с демо-блоками (показы есть, дохода нет).

Частоты показов (меняются по вкусу, значения по умолчанию разумные):

```properties
ads.interstitialEveryNthConversion=3      # межстраничная не раньше 3-й конвертации
ads.interstitialMinIntervalSeconds=120    # и не чаще раза в 2 минуты
ads.rewardedNoAdsMinutes=30               # сколько минут реклама скрыта за rewarded
```

Если создадите новые блоки — поменяйте только три строки с ID и пересоберите релиз.

### 3.2 `app/src/main/java/com/converterplus/app/Config.kt`

| Константа | Что стоит сейчас | Что делать |
|---|---|---|
| `SUPPORT_EMAIL` | `support.converterplus@gmail.com` | **заменить на свою почту** — она идёт в карточку RuStore и в письма из приложения |

| `APP_ADS_DOMAIN` | `kirillpetrov08.github.io` | домен разработчика, где лежит `app-ads.txt` |

### 3.3 `docs/app-ads.txt` и GitHub Pages

РСЯ проверяет файл `app-ads.txt` на сайте разработчика (сайт берётся из карточки магазина)
раз в сутки. Без файла часть DSP не покупает показы — деньги теряются молча.

1. Включить GitHub Pages: репозиторий → **Settings → Pages** → Source **Deploy from a branch**,
   Branch **main**, Folder **/docs** → **Save**. Через минуту файлы из `docs/` станут доступны:
   - политика: `https://kirillpetrov08.github.io/yandex2/privacy_policy.html`
   - app-ads.txt: `https://kirillpetrov08.github.io/yandex2/app-ads.txt`
2. В кабинете РСЯ открыть **Настройки → Общие → app-ads.txt** — там лежит готовый фрагмент
   с вашим publisher ID. Скопировать строку в `docs/app-ads.txt` вместо `ВАШ_PUBLISHER_ID`.
3. Проверить, что файл открывается по ссылке из п. 1, и что в кабинете РСЯ он не помечен
   как «не найден».

Если политику и `app-ads.txt` вы размещаете не на GitHub Pages — залейте эти два файла
на свой домен и поправьте `Config.PRIVACY_POLICY_URL` и `Config.APP_ADS_DOMAIN`.

### 3.4 Проверка, что заглушек не осталось

```cmd
findstr /s /n /c:"ВАШ_" /c:"example.com" /c:"demo-" app\src\main\java\*.kt gradle.properties docs\app-ads.txt
```

Команда должна найти только строку с `ВАШ_PUBLISHER_ID` — и только до того, как вы вставили
свой publisher ID. Файл `app/build.gradle.kts` специально содержит строки `demo-*` как
значения по умолчанию: они нужны для отладочных сборок без `gradle.properties`.

## 4. Как собирать

### 4.1 Debug-сборка — проверить, что всё живо

```bash
./gradlew assembleDebug          # macOS / Linux
gradlew.bat assembleDebug        # Windows
```

Файл: `app/build/outputs/apk/debug/app-debug.apk`, пакет `com.converterplus.app.debug`
(суффикс `.debug`, чтобы отладочная сборка не конфликтовала с релизной на одном телефоне).

Установка на подключённый телефон:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Переменные окружения для debug не нужны. Так как в `gradle.properties` уже стоят боевые ID,
debug-сборка показывает те же блоки, что и релиз (сейчас — тестовые креативы РСЯ).

### 4.2 Release-сборка — то, что уходит в RuStore

APK **обязан** быть подписан ключом приложения (`app-signing.keystore`, alias `sign`):
RuStore сам ничего не подписывает.

Windows (cmd), из корня проекта:

```cmd
set "JAVA_HOME=%ProgramFiles%\Android\Android Studio\jbr"
set "KEYSTORE_FILE=app-signing.keystore"
set "KEYSTORE_PASSWORD=пароль_от_keystore"
set "KEY_ALIAS=sign"
set "KEY_PASSWORD=пароль_от_ключа"
gradlew.bat clean assembleRelease
```

macOS / Linux:

```bash
export KEYSTORE_FILE=app-signing.keystore
export KEYSTORE_PASSWORD='пароль_от_keystore'
export KEY_ALIAS=sign
export KEY_PASSWORD='пароль_от_ключа'
./gradlew clean assembleRelease
```

Файл: `app/build/outputs/apk/release/app-release.apk`.
`KEYSTORE_FILE` считается от корня проекта — так же его подставляет CI.
Если переменные не заданы, сборка пройдёт, но APK останется неподписанным (`logger.warn`),
и магазин его не примет.

Проверка подписи (путь к build-tools подставьте свою версию):

```cmd
"%LOCALAPPDATA%\Android\Sdk\build-tools\36.0.0\apksigner.bat" verify --print-certs app\build\outputs\apk\release\app-release.apk
```

### 4.3 Через Android Studio

**Build → Generate Signed Bundle / APK → APK → release** → выбрать `app-signing.keystore`,
alias `sign`, пароли. Результат тот же — `app-release.apk` в `app/build/outputs/apk/release/`.
Удобно для разовой сборки; для повторяемых сборок используйте команды из 4.2.

### 4.4 Через GitHub Actions

Готовый воркфлоу — `docs/ci-android.yml`. Создаётся **вручную** в веб-интерфейсе GitHub
(Add file → Create new file → имя `.github/workflows/android.yml` → вставить содержимое):
push этого пути от бота отклоняется, у GitHub App нет права `workflows`.
Секреты репозитория: `KEYSTORE_BASE64` (`openssl base64 -A -in app-signing.keystore`),
`KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Артефакт сборки — `apk/release/app-release.apk`.

### 4.5 Что проверить перед сборкой релиза

- [ ] `versionCode` больше, чем у предыдущей загрузки в RuStore (`app/build.gradle.kts`);
- [ ] `ads.testMode=false` и три ID `R-M-20230616-*` в `gradle.properties` (уже так);
- [ ] ключ `app-signing.keystore`, alias `sign`, пароли под рукой;
- [ ] в `Config.kt` ваша почта, ссылка на политику и ссылка на карточку магазина;
- [ ] `docs/app-ads.txt` выложен по домену из `Config.APP_ADS_DOMAIN`.

## 5. Как убедиться, что реклама настоящая

Все события SDK пишутся в logcat с тегом **`ConverterAds`** (см. `ads/AdsLog.kt`):

```bash
adb logcat -s ConverterAds:V
```

На здоровой релизной сборке видно:

| Строка в логе | Что означает |
|---|---|
| `init: пропущено: согласие не получено` | до прохождения онбординга — норма: без согласия SDK не стартует |
| `SDK готов: <статус>, testMode=false` | SDK инициализирован, режим релизный |
| `interstitial: загружена` → `interstitial: закрыта` | межстраничная реально показывается |
| `rewarded: загружена` + выдача награды | rewarded-блок живой |

Тревожные строки:

| Строка | Причина | Что делать |
|---|---|---|
| `ERROR config: Некорректные ID рекламных блоков` | ID не совпал с шаблоном `R-M-…-Y` | скопировать ID из кабинета заново |
| `ERROR config: В релизной сборке остались демо-блоки` | в `gradle.properties` вернули `demo-*` | вписать реальные ID и пересобрать |
| `init: пропущено: согласие не получено` в релизе | пользователь не принял условия онбординга | это выбор пользователя, реклама просто не показывается |
| `WARN interstitial: code=…` | блок не загрузился: нет сети, модерация, лимит | проверить интернет и статус приложения в РСЯ |

Пока приложение не прошло модерацию РСЯ, на реальных ID показывается **тестовая реклама** —
это ожидаемо. Деньги начинаются только после статуса **Активно**.

## 6. От тестового режима до первых денег

1. Собрать релизный APK (раздел 4) — код уже настроен на ваши три блока.
2. Опубликовать приложение в RuStore (`docs/RUSTORE_DEPLOY.md`).
3. Открыть карточку приложения в РСЯ → добавить ссылку на RuStore
   (`https://www.rustore.ru/catalog/app/com.converterplus.app`). Это и есть действие,
   которого ждёт надпись «Добавить ссылку» на странице приложения.
4. После добавления ссылки приложение **заново уходит на модерацию РСЯ** — до 2 дней.
   До неё стоит статус **«Тестовый режим»**: на ваших ID показываются тестовые креативы.
5. Дождаться статуса **Активно** — с этого момента показы тарифицируются.
6. Проверить в кабинете РСЯ, что `app-ads.txt` найден (Настройки → Общие → app-ads.txt).

Важно: если в кабинете когда-нибудь нажимали **«Остановить»** на странице приложения,
показы не вернутся сами — нужно нажать **«Включить показы»**.

## 7. Типичные ошибки

| Ошибка | Что происходит | Лечение |
|---|---|---|
| ID от другого приложения | запросы уходят, показов нет | ID копировать из карточки **своего** приложения в РСЯ |
| Перепутаны блоки местами | межстраничная не показывается из-за чужого ID | сверить три строки в `gradle.properties` с тремя блоками в кабинете |
| Осталось `ads.testMode=true` | реклама тестовая, дохода нет | поставить `false`, пересобрать |
| Сборка падает с сообщением про ID | сработала защита в `app/build.gradle.kts` | вписать ID вида `R-M-XXXXXXX-Y` |
| Баннер не виден | не дано согласие, активен режим «без рекламы», или экран без баннера (настройки, онбординг) | проверить лог `ConverterAds` и «Убрать рекламу» |
| Персонализация и возрастной рейтинг | с персонализированной рекламой RuStore требует рейтинг **12+**, а не 6+ | рейтинг в карточке RuStore выставлен 12+ |
| Хочется «рекламу при открытии» | запрещена ТЗ и не интегрирована | не подключать |
