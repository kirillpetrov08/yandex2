# Публикация «Конвертер+» в RuStore — полный гайд

> Гайд написан под этот проект (`com.converterplus.app`, minSdk 26, versionCode 1) и
> соответствует правилам RuStore, действующим на момент написания.
> Всё, что касается подписи и ключей, подробно разобрано отдельно — `docs/RUSTORE_SIGNING.md`.
> Всё, что касается сборки релизного APK и рекламы РСЯ — `docs/APK_RELEASE.md`.
> Этот файл — про **сам процесс публикации**: от регистрации аккаунта до ссылки на карточку,
> которую вы вставите в кабинет РСЯ.

---

## 0. Что получится и сколько времени это займёт

| Шаг | Что делаете | Сколько занимает |
|---|---|---|
| 1 | Регистрация разработчика (VK ID + VK Бизнес) | 20–40 минут |
| 2 | Сборка подписанного APK | 15 минут |
| 3 | Материалы карточки (иконка, 3+ скриншота, тексты, URL политики) | 1–2 часа |
| 4 | Создание приложения и загрузка APK в консоль | 20 минут |
| 5 | Заполнение карточки версии и деклараций | 30–60 минут |
| 6 | Модерация RuStore | **до 72 часов** (официальный срок) |
| 7 | Ссылка на карточку → в кабинет РСЯ (модерация РСЯ до 2 дней) | 10 минут |
| 8 | Реклама начинает платить | только после статуса **Активно** в РСЯ |

Важно: **«APK опубликован» и «реклама платит» — не одно и то же.** До прохождения модерации
РСЯ на реальных блоках показывается тестовая реклама без вознаграждения. Приложение при этом
можно и нужно публиковать в RuStore заранее — как раз чтобы ссылку было куда вставить.

## 2. Регистрация разработчика в RuStore

1. Открыть <https://console.rustore.ru/sign-in> и войти через **VK ID**.
   Регистрация бесплатная, при первом входе создаётся бизнес-профиль VK Бизнес.
2. Пройти регистрацию как **юридическое лицо / ИП** или как **физическое лицо**:
   - ЮЛ и ИП — регистрационную форму нужно подписать **квалифицированной электронной подписью**;
   - физлицо — подходит для личного использования, порядок проще.
   Подробности: <https://www.rustore.ru/help/developers/developer-account/registration-developer>
3. Заполнить контакты разработчика — **публичный e-mail обязателен**: по нему модерация
   задаёт вопросы и по нему приходят результаты проверки. Контакт в профиле должен совпадать
   с реальным, иначе можно пропустить запрос и получить отказ по «отсутствию ответа».
4. Роли (пригодится, если работает команда):

| Роль | Может |
|---|---|
| Владелец компании | добавить новое приложение, загрузить версию |
| Администратор | загрузить версию, менять настройки |
| Релиз-менеджер | загрузить версию |
| Разработчик | загрузить версию |

> Загрузить **первую** версию может только «Владелец компании». Если аккаунт один — это вы.

## 3. Сборка подписанного APK для RuStore

### 3.1 Ключ подписи — один на все магазины

RuStore **не переподписывает** прямой APK: файл должен быть подписан вашим
**ключом подписи приложения** (в проекте — `app-signing.keystore`, alias `sign`).
Если ключ RuStore отличается от ключа, которым подписана версия в другом магазине,
пользователи не смогут обновить приложение — получат ошибку установки.

- Ключ один и тот же для Google Play, RuStore и любых прямых раздач.
- Ключ **никогда не удаляется и не пересоздаётся** — пересоздание ломает обновления.
- Смена ключа в RuStore — только через поддержку `support@rustore.ru`.
- Полный разбор двух ключей (upload-key и app signing key), PEPK и команд Windows/macOS
  лежит в `docs/RUSTORE_SIGNING.md`; вспомогательные скрипты — `tools/rustore-signature.cmd`
  и `tools/rustore-signature.sh`.

### 3.2 Поднять версию

В `app/build.gradle.kts`:

```kotlin
versionCode = 1          // ПЕРЕД КАЖДОЙ загрузкой в RuStore: +1
versionName = "1.0.0"    // человекочитаемая версия
```

Правило RuStore: номер новой версии (versionCode) должен быть **больше предыдущего**.

### 3.3 Реальные рекламные ID и выключенный тестовый режим

В `gradle.properties` должны стоять реальные ID вида `R-M-XXXXXXX-Y` и `ads.testMode=false`.
Пока этого не сделано, в APK едут демо-блоки — такой файл в магазин отправлять нельзя
(приложение покажет тестовую рекламу и не заработает денег). Раздел 2
в `docs/APK_RELEASE.md` — таблица замен.

### 3.4 Сборка: Windows

```cmd
set "JAVA_HOME=%ProgramFiles%\Android\Android Studio\jbr"
set "KEYSTORE_FILE=app-signing.keystore"
set "KEYSTORE_PASSWORD=пароль_от_keystore"
set "KEY_ALIAS=sign"
set "KEY_PASSWORD=пароль_от_ключа"
gradlew.bat clean assembleRelease
```

PowerShell — те же переменные:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:KEYSTORE_FILE = "app-signing.keystore"
$env:KEYSTORE_PASSWORD = "пароль_от_keystore"
$env:KEY_ALIAS = "sign"
$env:KEY_PASSWORD = "пароль_от_ключа"
.\gradlew.bat clean assembleRelease
```

### 3.5 Сборка: macOS / Linux

```bash
export KEYSTORE_FILE=app-signing.keystore
export KEYSTORE_PASSWORD='пароль_от_keystore'
export KEY_ALIAS=sign
export KEY_PASSWORD='пароль_от_ключа'
./gradlew clean assembleRelease
```

Готовый файл: **`app/build/outputs/apk/release/app-release.apk`**
(`KEYSTORE_FILE` отсчитывается от корня проекта — так делает CI, см. `docs/ci-android.yml`;
в CI keystore восстанавливается из секрета `KEYSTORE_BASE64`).

### 3.6 Проверки до загрузки

```cmd
"%LOCALAPPDATA%\Android\Sdk\build-tools\36.0.0\apksigner.bat" verify --print-certs ^
  app\build\outputs\apk\release\app-release.apk
```

```bash
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --print-certs \
  app/build/outputs/apk/release/app-release.apk
```

Чек-лист:

- [ ] `apksigner` показывает ваш ключ подписи приложения (не debug-ключ);
- [ ] в выводе есть `Verified using v2/v3 scheme: true`;
- [ ] `versionCode` больше, чем у предыдущей загрузки в RuStore;
- [ ] файл меньше 5 ГБ (у нас — десятки мегабайт);
- [ ] APK **установлен на живой телефон** и проверен руками: изображения, PDF → изображения,
      изображения → PDF, аудио, видео, распознавание текста;
- [ ] на экранах нет демо-баннеров, в логах нет `в релизной сборке остались демо-блоки`;
- [ ] нет разрешений на хранилище, камеру, микрофон (в RuStore это смотрят).

## 5. Загрузка APK

Официальные требования к файлу APK:

| Требование | У нас |
|---|---|
| размер ≤ 5 ГБ | ~30 МБ (включая 7,7 МБ данных OCR) |
| подписан цифровым сертификатом | `app-signing.keystore` |
| уникальное имя пакета | `com.converterplus.app` |
| сборка проверена и настроена | шаг 3.6 |
| **для 2-й и последующих версий**: подпись совпадает с предыдущей, пакет тот же, versionCode больше | контролируется поднятием версии |

Загрузка идёт в два этапа:

1. **Загрузка** — страницу нельзя покидать, иначе процесс прервётся.
2. **Обработка** — можно сохранить черновик и уйти, обработка продолжится в фоне.
   Если валидация найдёт ошибку, консоль её покажет (чаще всего — «подпись не совпадает»
   или «версия не больше предыдущей»).

После обработки файлы хранятся **14 дней**: если за это время не отправить версию
на модерацию, их удалят и APK придётся загружать заново.

Блок **Разметка файлов** появляется, только если загружено несколько файлов.
У нас файл один — считается основным, ничего размечать не нужно.
(Если когда-нибудь соберёте отдельные сборки под Huawei/Honor или подпись для другого
магазина — «Основным» выбирается файл, чья подпись отличается от подписи Google Play.)

## 6. Карточка версии: что писать в каждое поле

### 6.1 Информация о приложении

| Поле | Ограничение | Что указывать |
|---|---|---|
| Наименование | ≤ 30 символов, уникально | `Конвертер+ — PDF и фото` (22 символа) |
| Тип приложения | — | неигровое приложение |
| Категория основная | из списка | **Полезные инструменты** (сюда попадают приложения для работы с документами и утилиты) |
| Категория дополнительная | необязательно | **не указывать** — правилами категории «Полезные инструменты» запрещено назначать её второй категорией |
| Возрастное ограничение | 0+/6+/12+/16+/18+ | **12+** — см. пояснение ниже |
| Поисковые теги | до 5 | `конвертер`, `pdf`, `jpg`, `png`, `документы` |
| Краткое описание | ≤ 80 символов | `Офлайн-конвертер: JPG, PNG, WEBP и PDF прямо на телефоне.` |
| Полное описание | ≤ 4000 символов | из `docs/STORE_TEXTS.md`, раздел 2 (RuStore) |
| Минимальная версия Android | подтягивается из манифеста | автоматически: minSdk 26 → **Android 8.0** |

**Почему 12+, а не 6+.** По правилам RuStore (п. 9.7) в приложениях с возрастной
категорией **0+ и 6+ запрещена поведенческая (персонализированная) реклама** — допускается
только неперсонализированная. Наш рекламный блок в РСЯ персонализируется, поэтому
корректная маркировка — **12+**. Если бы понадобилось оставить 6+, пришлось бы отключать
персонализацию в настройках РСЯ и подтверждать это при публикации.

> `docs/STORE_TEXTS.md` в этом пункте приведён в соответствие: возрастной рейтинг 12+,
> реклама — да.

### 6.2 Способы связи с разработчиком

Обязательно **хотя бы одно** поле; у нас — публичный e-mail поддержки. При обновлениях
значения подтягиваются из предыдущей версии, менять можно.

### 6.3 Медиафайлы

Иконка:

- 512×512 px, ≤ 3 МБ, `.png` или `.jpg`;
- **фон залит по всей площади**, без прозрачных и пустых участков по контуру.

Скриншоты (обязательны для мобильной версии):

- **не менее 3** для каждого типа устройств, за раз можно добавить 1–10;
- `.png`/`.jpg`, до 3 МБ (телефон) и до 5 МБ (планшет);
- максимальное разрешение 2160×3840, рекомендуемое соотношение 16:9;
- выбрать ориентацию (у нас — вертикальная).

Что снять: главная с инструментами, выбор файла, выбор формата, прогресс конвертации,
результат, история. Планшетные скриншоты можно не загружать — тогда на планшетах
покажутся телефонные.

Видео в карточке — только ссылкой на **VK Видео** (`vk.ru`, `vk.com`, `vkvideo.ru`),
необязательно. Поле **Фоновое видео** — тоже опционально, играет без звука.

### 6.4 Что нового?

Обязательный при обновлениях, но заполняйте и в первой версии — коротко:
«Первый выпуск: изображения (JPG/PNG/WEBP), PDF → изображения, изображения → PDF,
аудио и видео, распознавание текста, конвертация в фоне».

### 6.5 FAQ (необязательно, но полезно)

До 10 пар, вопрос ≤ 120 символов, ответ ≤ 500. Показывается только в веб-версии карточки.
Готовые формулировки под наш проект:

| Вопрос | Ответ |
|---|---|
| Нужен ли интернет для конвертации? | Нет. Все файлы обрабатываются на устройстве. Интернет нужен только для показа рекламы. |
| Приложение просит доступ к файлам? | Нет. Файл выбирается через системное окно, доступ выдаётся только к выбранному файлу. |
| Почему на фото водяной знак? | Бесплатная версия добавляет небольшую надпись «Конвертер+» на изображения и PDF. Убрать её можно за просмотр короткого видео. |
| Какие форматы поддерживаются? | Вход: JPG, PNG, WEBP, HEIC (Android 9+), AVIF (Android 12+), PDF, аудио и видео. Выход: JPG, PNG, WEBP, PDF, TXT, WAV, M4A, OGG/Opus (Android 10+), MP4. |
| Есть ли подписка? | Нет. Только реклама — покупок и подписок в приложении нет. |

## 7. Блок «Безопасность данных пользователя»

Заполняется **для всех версий** и состоит из двух частей.

### 7.1 Чувствительные разрешения

Раздел показывается, только если в APK найдены опасные (dangerous), специальные (special)
или требующие особой подписи (signature) разрешения. Что есть у нас:

| Разрешение | Тип | Покажется в разделе |
|---|---|---|
| `INTERNET` | normal (безопасное) | нет |
| `ACCESS_NETWORK_STATE` | normal | нет |
| `FOREGROUND_SERVICE` | normal | нет |
| `FOREGROUND_SERVICE_DATA_SYNC` | normal | нет |
| `POST_NOTIFICATIONS` | **dangerous** (запрашивается у пользователя с Android 13) | **да** — потребуется обоснование |

Для `POST_NOTIFICATIONS` в поле **Обоснование** вставьте готовый текст:

> Разрешение на уведомления нужно, чтобы показывать прогресс конвертации файла в шторке
> уведомлений при работе в фоне. Запрашивается не при первом запуске, а только в момент
> первой конвертации; без него приложение полностью работоспособно, а уведомление просто
> не появится. Других разрешений приложение не запрашивает: файлы выбираются через системные
> диалоги, камера, микрофон и доступ к хранилищу не используются.

Если у вас в релизной сборке случайно окажется разрешение на хранилище, камеру или микрофон —
это повод пересобрать APK, а не писать обоснование: в проекте таких разрешений быть не должно.

### 7.2 Категории и типы данных

Консоль **автоматически** заполняет список по разрешениям из манифеста — проверьте и
дополните руками. Для «Конвертер+»:

| Тип данных | Отмечать? | Почему |
|---|---|---|
| ID устройства или другие идентификаторы | **Да** | рекламный SDK Яндекс РСЯ передаёт рекламный идентификатор |
| Взаимодействие с приложением | **Да, если есть в списке** | SDK собирает статистику показов и кликов |
| Файлы и документы | Нет | файлы пользователя не покидают устройство |
| Фото и видео, аудиофайлы | Нет | обрабатываются локально |
| Местоположение, контакты, сообщения, финансы | Нет | не запрашиваются |
| Отчёты об ошибках, диагностика | Нет | crash-репортинг не подключён |

Готовое обоснование, которое можно вставить в поле пояснения:

> Приложение обрабатывает выбранные пользователем файлы только на устройстве и никуда их
> не передаёт. Интернет используется исключительно для загрузки рекламы Яндекс РСЯ.
> Рекламный SDK передаёт рекламный идентификатор устройства и данные о показах —
> это указано в политике конфиденциальности.

### 7.3 Декларации

- **Рекламные SDK и сети** — обязателен к декларированию **весь** список. У нас: *Yandex
  Mobile Ads (РСЯ, `com.yandex.android:mobileads`)*, форматы — баннер, межстраничная,
  за вознаграждение. Незадекларированный рекламный SDK — основание снять приложение
  с публикации.
- **Платёжные решения** — нет ни встроенных покупок, ни подписок, ни внешних платежей.
  Так и укажите: приложение бесплатное.
- Никаких механизмов, мешающих распространению через RuStore (Google Play Integrity
  и подобное), в проекте нет — это требование п. 8.4.2 правил, и его нарушение ведёт
  к снятию с публикации.

## 8. Настройка публикации версии

| Режим | Как работает | Когда выбирать |
|---|---|---|
| **Автоматически / мгновенно** | после модерации версия публикуется в течение часа | когда уверены в сборке |
| **Вручную** | после модерации получаете статус «Готова к публикации» и жмёте **Опубликовать** | **рекомендуется для первой версии**: успеваете прочитать письмо модератора |
| **В выбранную дату и время** | отложенная публикация, доступна при обновлении | для запланированных релизов |
| **Поэтапно, 1–100 %** | доступна при обновлении: случайная доля пользователей, процент можно только увеличивать | для рискованных обновлений |

Снять версию с публикации можно в любой момент: активируется последняя активная версия,
но у тех, кто уже обновился, останется новая.

## 9. Модерация

Что происходит после нажатия **Отправить на модерацию**:

| Этап | Что проверяют |
|---|---|
| Автоматическая проверка безопасности | антивирус (Kaspersky), уязвимости (MobSF) |
| Проверка модератором | контент, функциональность, метаданные |
| Специализированная проверка | если нужна — ИБ и соответствие требованиям законодательства |

**Срок: до 72 часов.** При первой публикации модерация вправе запросить дополнительные данные.

Частые причины отказа (официальный список):

- неработоспособность или низкое качество приложения;
- недостоверные сведения в карточке (например, обещаны функции, которых нет);
- отсутствие политики конфиденциальности или обработка данных не по закону;
- нарушение требований к рекламе, монетизации, детским приложениям;
- недекларированные рекламные SDK или платёжные решения;
- нарушение прав интеллектуальной собственности;
- отсутствие обязательной маркировки или сведений.

Если отказ: в уведомлении будут конкретные причины. ПравИте карточку в консоли и снова
жмёте **Отправить на модерацию**; если причина в самом приложении — собираете новую версию
(`versionCode + 1`) и загружаете APK заново. Апелляцию на решение можно подать письмом
на `support@rustore.ru` — одна апелляция на решение, срок рассмотрения до 30 календарных дней.

## 10. После публикации

1. Скопировать ссылку на карточку приложения — в консоли у версии есть действие
   со ссылкой (адрес имеет вид `https://www.rustore.ru/catalog/app/com.converterplus.app`;
   берите точное значение из консоли, не набирайте руками).
2. Вставить её в кабинете РСЯ в карточку приложения (для приложений, которые ещё не были
   в магазине, добавляется ссылка на стор). После добавления ссылки приложение
   **заново уходит на модерацию РСЯ**; до статуса **Активно** показывается тестовая реклама.
3. Проверить, что `docs/app-ads.txt` лежит в корне сайта разработчика и в кабинете РСЯ
   в настройках общий фрагмент скачивается без ошибок.
4. Установить версию из RuStore на тестовый телефон **поверх версии из другого магазина** —
   установка должна пройти без ошибки подписи (проверка «одного ключа»).
5. Включить в консоли уведомления о новых отзывах и отвечать на них: шаблонные ответы
   правилами RuStore запрещены, а жаловаться на отзывы можно только за спам,
   мат, чужие персональные данные или заведомую ложь.

## 11. Обновления версий

1. Поднять `versionCode` в `app/build.gradle.kts`, при необходимости — `versionName`.
2. Собрать APK **тем же** ключом.
3. Консоль → приложение → **Загрузить версию** → заполнить **Что нового?**.
4. Проверить, что контактные данные и описания актуальны.
5. Выбрать режим публикации (для обычного обновления достаточно автоматического,
   для рискованного — поэтапный с 10 %).
6. Отправить на модерацию.

Правила, которые легко забыть:

- **нельзя** менять имя пакета — обновление не установится;
- нельзя менять ключ подписи (только через поддержку RuStore);
- RuStore вправе снять приложение с публикации, если **12 месяцев** нет обновлений
  или версия в RuStore отстаёт от версии в других магазинах;
- если у приложения есть авторизация, она должна работать без сторонних ресурсов;
- приложение должно стабильно работать на поддерживаемых версиях Android.

## 12. Чего RuStore не прощает — и как мы это выполняем

| Требование RuStore | Как выполнено в «Конвертер+» |
|---|---|
| Реклама отделена от контента и обозначена (п. 9.5) | баннер в отдельном контейнере фиксированной высоты, ≥ 12 dp от кнопок |
| Нельзя маскировать рекламу под интерфейс, показывать её вне сеанса работы, без кнопки закрытия (п. 9.6) | реклама не показывается в онбординге, настройках, во время конвертации и в шторке результата; межстраничная — только после закрытия шторки |
| В приложениях 0+ и 6+ запрещена поведенческая реклама (п. 9.7) | возрастная категория **12+** |
| Незадекларированные рекламные SDK запрещены (п. 9.4) | в карточке декларируется Yandex Mobile Ads (РСЯ) |
| Политика конфиденциальности: ссылка в карточке **и** внутри приложения, на русском, с категориями данных, целями, сроками и контактом (п. 5.1) | `docs/privacy_policy.html` + пункт «Политика конфиденциальности» в настройках приложения |
| Приложение не должно быть заглушкой и не работать (п. 8.1) | шесть инструментов работают: изображения, PDF → изображения, изображения → PDF, аудио, видео, распознавание текста |
| Приложение должно работать с Android 8.0+ (п. 8.1) | minSdk 26 |
| Нельзя мешать распространению через RuStore (п. 8.4.2) | Google Play Integrity и подобные механизмы не используются |
| Русский язык в интерфейсе (ФЗ-168, с 01.03.2026) | все строки в `strings.xml` на русском, английской локализации нет |
| Маркировка интернет-рекламы (ФЗ-38, ЕРИР) | маркировку выполняет Яндекс как оператор рекламных данных — от разработчика в кабинете РСЯ заполняются данные приложения |
| Персональные данные (ФЗ-152) | файлы не покидают устройство; в политике описано, какие данные обрабатывает рекламный SDK. Если вы как владелец приложения подпадаете под статус оператора ПД — подайте уведомление в РКН (ст. 22 ФЗ-152) и держите документы готовыми: RuStore вправе их запросить |

## 14. Типовые ошибки и что делать

| Симптом | Причина | Решение |
|---|---|---|
| «Подпись не совпадает с предыдущей» | APK собран другим ключом | пересобрать APK с `app-signing.keystore`; смена ключа — только через `support@rustore.ru` |
| «Версия не больше предыдущей» | забыли поднять `versionCode` | `versionCode + 1`, пересборка, повторная загрузка |
| Файл исчез из черновика | прошло 14 дней без отправки на модерацию | загрузить APK заново |
| Загрузка оборвалась, есть ошибка валидации | ушли со страницы на этапе **Загрузки** | повторить, не покидая страницу до перехода к обработке |
| Отказ «недостоверные сведения» | в описании обещано то, чего нет (например, HEIC на выходе) | убрать обещания из `docs/STORE_TEXTS.md`, пересобрать карточку |
| Отказ «нет политики конфиденциальности» | ссылка не открывается или политики нет внутри приложения | проверить URL и пункт в настройках |
| Отказ из-за рекламы | SDK не задекларирован, реклама мешает управлению, показывается вне сессии | заполнить декларацию, проверить, что баннер не перекрывает кнопки |
| Вопрос модератора про `POST_NOTIFICATIONS` | разрешение относится к чувствительным | вписать обоснование из раздела 7.1 |
| Возраст 6+ и поведенческая реклама | правила RuStore запрещают персонализацию в 0+ и 6+ | поставить 12+ |
| Приложение сняли из каталога | нет обновлений > 12 месяцев или версия отстаёт от другого магазина | выпустить актуальную версию и подать на модерацию |
| Консоль не даёт добавить приложение | у роли нет прав | добавить приложение может только «Владелец компании» |
