# Релизный APK «без заглушек» — пошагово

Цель: получить подписанный `app-release.apk`, в котором нет ни одного демо-значения,
реклама подключена к реальным блокам РСЯ, и который можно сразу отдать в RuStore.

Важно понимать сразу: **технически «готовый к показам» APK и «показы, за которые платят» —
это два разных момента.** Приложение в РСЯ проходит модерацию до 2 дней, и до статуса
**Активно** на реальных блоках показывается тестовая реклама без вознаграждения
(официально: «Показы настоящей рекламы начнутся после того, как приложение пройдёт
модерацию»). Поэтому порядок такой: собрать APK → залить в RuStore → добавить ссылку
на приложение в РСЯ → дождаться «Активно» → реклама начинает платить.

## 0. Что такое «заглушки» в этом проекте

| Категория | Что это | Действие |
|---|---|---|
| **Рекламные блоки** | `ads.bannerUnitId` и др. в `gradle.properties` | уже вписаны боевые ID `R-M-20230616-2` / `-4` / `-7` и `ads.testMode=false`; менять только при создании новых блоков |
| **Контакты и домен** | `Config.kt`, `docs/privacy_policy.html`, `docs/STORE_TEXTS.md` | **уже заполнены**: `kirillpetrov08@gmail.com`, политика на `https://kirillpetrov08.github.io/converterplus/privacy-policy.html` |
| **Publisher ID** | `docs/app-ads.txt` | **уже вписан**: `yandex.com, 110347355, DIRECT`, файл опубликован в корне сайта |
| **Версия сборки** | `versionCode 2` / `versionName "1.0.1"` | поднять перед каждой загрузкой в магазин (в CI — полем `version_code` в форме запуска) |
| **Инструменты на главной** | все шесть: изображения, PDF → фото, фото → PDF, извлечение текста, аудио, видео | **заглушек нет**: этапы 1–4 реализованы, все инструменты работают |

Проверить, что плейсхолдеров не осталось, можно поиском:

```cmd
findstr /s /n /c:"ВАШ_" /c:"demo-" /c:"support.converterplus" /c:"example.com" app\src\main\java\*.kt docs\*.html docs\STORE_TEXTS.md gradle.properties
```

В коде приложения, в политике и в текстах магазинов команда не должна ничего найти.
Строки `demo-*` в `app/build.gradle.kts` и `ads/AdUnits.kt` — это значения по умолчанию
для отладочных сборок без `gradle.properties`, они там нужны намеренно.

## 1. Реклама Яндекс РСЯ: блоки и настройки

Полный порядок — в `docs/ADS_SETUP.md`; здесь только суть.

1. Открыть <https://partner.yandex.ru> → раздел **Реклама в приложениях** → **Добавить приложение**.
2. Если приложение ещё не в магазине — выбрать **«Моё приложение ещё не опубликовано»**
   (после публикации нужно будет добавить ссылку на RuStore или Google Play).
3. Указать платформу Android и имя приложения (например, `Конвертер+`).
4. Подтвердить доступ к приложению — уникальным кодом или файлом `app-ads.txt`
   (см. раздел 7).
5. Создать **три** блока, у каждого свой ID вида `R-M-1234567-1`:

| Формат | Что подключено в коде | Где показывается |
|---|---|---|
| Баннер | `bannerUnitId` | главная и история (внизу), экран инструмента |
| Межстраничная (interstitial) | `interstitialUnitId` | после закрытия шторки с результатом, не чаще 3-й конвертации и 1 раза в 120 с |
| Rewarded | `rewardedUnitId` | по кнопке: убрать рекламу на 30 минут или снять ограничение на большое фото |

ID копируются в интерфейсе РСЯ. **Формат жёстко проверяется:** `R-M-<цифры>-<цифра>`,
шаблон `^R-M-\d{4,}-\d{1,3}$` в `AdUnits.kt`.

## 2. `gradle.properties`: реальные ID и выключенный тестовый режим

Открыть `gradle.properties` в корне проекта и заменить блок «Реклама Яндекс РСЯ»:

```properties
ads.testMode=false
ads.bannerUnitId=R-M-1234567-1
ads.interstitialUnitId=R-M-1234567-2
ads.rewardedUnitId=R-M-1234567-3
ads.interstitialEveryNthConversion=3
ads.interstitialMinIntervalSeconds=120
ads.rewardedNoAdsMinutes=30
```

Две защиты уже встроены и сработают сами:

- если `ads.testMode=false`, а хоть один ID не подходит под шаблон `^R-M-\d{4,}-\d{1,3}$`
  (демо-строка или опечатка), **сборка падает** с текстом
  «ID блоков не похожи на реальные (нужен вид R-M-XXXXXXX-Y): ads.bannerUnitId=…» —
  это защита от публикации с демо-блоками (показы без дохода);
- при запуске приложения в лог пишется конфигурация, по которой видно режим:
  `adb logcat -s ConverterAds` → `SDK готов: Initialized, testMode=false`.

Три нижних параметра — правила показа, их можно менять по вкусу. Они влияют на то,
как часто пользователь видит рекламу: третий параметр равен числу конвертаций между
межстраничными, остальные — временные интервалы.

## 3. Контакты, домен и publisher ID

| Файл | Что заменить |
|---|---|
| `app/src/main/java/com/converterplus/app/Config.kt` | уже заполнено: `SUPPORT_EMAIL = "kirillpetrov08@gmail.com"`, `PRIVACY_POLICY_URL` → опубликованная страница, `APP_ADS_DOMAIN = "kirillpetrov08.github.io"`; менять только `STORE_URL` после публикации |
| `docs/privacy_policy.html` | копия опубликованной страницы (оригинал — на сайте, см. ниже) |
| `docs/STORE_TEXTS.md` | почта, сайт и ссылка на политику — уже вписаны в описания для магазинов |
| `docs/app-ads.txt` | копия файла, опубликованного по адресу `https://kirillpetrov08.github.io/app-ads.txt` |

Почему это важно для денег: часть DSP-сетей не покупает показы, если `app-ads.txt` не
опубликован; кроме того, файл — один из способов подтвердить доступ к приложению,
без подтверждения приложение не выйдет из тестового режима.

## 4. Сборка APK

### Вариант A. Командная строка, Windows (основной путь)

```cmd
cd /d C:\путь\к\yandex2

rem JDK: у кого стоит Android Studio — отдельно ставить не нужно
set "JAVA_HOME=%ProgramFiles%\Android\Android Studio\jbr"

rem подпись берётся из переменных окружения (см. app/build.gradle.kts)
set "KEYSTORE_FILE=app-signing.keystore"
set "KEYSTORE_PASSWORD=пароль_хранилища"
set "KEY_ALIAS=sign"
set "KEY_PASSWORD=пароль_ключа"

gradlew.bat clean assembleRelease
```

Результат: `app\build\outputs\apk\release\app-release.apk`.
Без секретов ключа файл неподписан: AGP кладёт его как `app-release-unsigned.apk`, а сборка
дополнительно копирует под обычным именем `app-release.apk` (см. `aliasUnsignedReleaseApk`
в `app/build.gradle.kts`) — так артефакт с APK появляется и до настройки подписи.
Такой APK ставится на телефон для проверки, но RuStore его не примет: для магазина
нужны четыре секрета (`docs/CI_BUILD.md`, шаг B).

`KEYSTORE_FILE` отсчитывается от корня проекта; можно указать и полный путь.
Если файла ключа нет — см. раздел 5.

Две тонкости: переменные должны быть заданы **в той же консоли**, из которой запускается
`gradlew.bat` (в новом окне их снова не будет), а запуск сборки из Android Studio эти
переменные не увидит — там используйте вариант D или задайте путь в
`Settings` → `Build, Execution, Deployment` → `Build Tools` → `Gradle` → `Environment variables`.

### Вариант B. macOS / Linux

```bash
export KEYSTORE_FILE=app-signing.keystore
export KEYSTORE_PASSWORD='пароль_хранилища'
export KEY_ALIAS=sign
export KEY_PASSWORD='пароль_ключа'
./gradlew clean assembleRelease
```

### Вариант C. Через CI (если локально нет Android Studio)

Воркфлоу собирает и APK, и AAB: шаг «Сборка (APK + AAB)» выполняет
`./gradlew assembleDebug assembleRelease bundleRelease`, а артефакты складываются
в `build-outputs`. Скачать APK: GitHub → Actions → последний прогон → **Artifacts** →
`build-outputs` → `apk/release/app-release.apk` (внутри артефакта пути отсчитываются
от `app/build/outputs`).

Для этого в секретах GitHub (`Settings` → `Secrets and variables` → `Actions`) должны
лежать `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
`KEYSTORE_BASE64` — содержимое того же keystore, что и в разделе 5:

```bash
openssl base64 -A -in app-signing.keystore
```

> Воркфлоу лежит в `docs/ci-android.yml` и создаётся в веб-интерфейсе GitHub руками:
> push файла `.github/workflows/*` от бота отклоняется. Если файл уже создан раньше —
> вставьте актуальную версию заново, в ней появился `assembleRelease` и проверка подписи APK.

### Вариант D. Android Studio

`Build` → `Generate Signed Bundle / APK` → **APK** → указать keystore, alias и пароли →
`release` → `Create`. Android Studio спросит keystore сама, значения из пункта A
в этом случае не нужны.

## 5. Каким ключом подписывать APK

**Правило: подпись, которую видят пользователи, — это подпись того ключа, которым подписан APK,
загруженный напрямую.** Магазины перевыпускают сборку под своим ключом только когда вы
грузите **AAB**; прямой APK отдаётся как есть.

Следствие для этого проекта: APK для RuStore (и любого другого прямого магазина) нужно
подписывать **ключом подписи приложения** — `app-signing.keystore`, alias `sign`,
то есть тем же, который уходит в магазины через PEPK. Тогда, когда вы позже перейдёте
на AAB, подпись не изменится и обновления встанут поверх.

- Ключ создаётся один раз:

```cmd
"%JAVA_HOME%\bin\keytool" -genkeypair -v -keystore app-signing.keystore -alias sign ^
  -keyalg RSA -keysize 4096 -validity 10000 -storetype PKCS12
```

- **Файл и пароль сохранить в двух местах.** Потеря = невозможность выпускать обновления.
- В git ключ не попадёт: `*.keystore`, `*.jks`, `*.pem` уже в `.gitignore`.
- Если вы сознательно держите два ключа (как рекомендует Google: ключ загрузки отдельно
  от ключа подписи), правило остаётся тем же: **APK подписывается ключом подписи приложения**,
  а ключ загрузки нужен только для AAB. Подробности — `docs/RUSTORE_SIGNING.md`.

## 6. Проверка готового APK

```cmd
rem 1. Подпись и её отпечаток (SHA-256 пригодится для сверки с магазином)
"%LOCALAPPDATA%\Android\Sdk\build-tools\36.0.0\apksigner.bat" verify --print-certs ^
  app\build\outputs\apk\release\app-release.apk

rem 2. Установка на подключённое устройство
"%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe" install -r ^
  app\build\outputs\apk\release\app-release.apk

rem 3. Смотрим, что делает реклама
"%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe" logcat -s ConverterAds
```

Что должно быть видно после первого запуска (онбординг → согласие → главный экран):

| Строка в логе | Что означает |
|---|---|
| `init: пропущено: согласие не получено` | нормально до прохождения онбординга: SDK намеренно не стартует без согласия |
| `SDK готов: Initialized, testMode=false` | SDK инициализирован, режим релизный |
| `config: Некорректные ID рекламных блоков` | ID не совпадает с форматом `R-M-…-Y` |

Плюс визуально: баннер фиксированной высоты внизу главной и истории, межстраничная —
после закрытия шторки результата (не раньше 3-й конвертации), rewarded — по кнопке
«Убрать рекламу на 30 минут».

Тесты чистой логики (рекомендую прогнать перед сборкой — они проверяют в том числе
правила показа рекламы):

```cmd
gradlew.bat testDebugUnitTest
```

## 7. Честная хронология: когда реклама начнёт платить

По документации РСЯ:

1. После создания приложение получает статус **Pending review** и уходит на модерацию —
   **до 2 дней**. Блоки создавать и подключать можно сразу, но вознаграждение за показы
   в это время не начисляется.
2. Если приложение ещё не опубликовано в магазине, оно числится в статусе **Тестовый режим**.
   На реальных блоках будут показываться **тестовые** объявления — это нормальный способ
   убедиться, что интеграция работает, но денег они не приносят.
3. После публикации в RuStore добавьте ссылку на приложение в РСЯ (или данные приложения
   из другого магазина) — приложение автоматически уйдёт на модерацию.
4. После статуса **Активно** начинаются настоящие показы и начисляется доход.

**`app-ads.txt`:** положите файл `docs/app-ads.txt` в корень домена разработчика так,
чтобы он открывался по адресу `https://ваш-домен/app-ads.txt`. Домен должен быть указан
на странице приложения в магазине — платформы берут его оттуда и проверяют файл раз в сутки.
Если файла нет или он устарел, часть покупателей не станет покупать показы.

## 8. Публикация

1. Поднять версию в `app/build.gradle.kts`: `versionCode` +1 (для каждой новой загрузки
   в магазин он должен быть больше предыдущего), `versionName` — по смыслу.
2. RuStore: `Загрузить версию` → приложить `app-release.apk`. **Подпись приложения при
   загрузке APK не запрашивается** — этот шаг нужен только для AAB.
3. Тексты, рейтинг, скриншоты — из `docs/STORE_TEXTS.md`, «содержит рекламу — да»,
   «покупок нет».
4. Добавить ссылку на приложение в кабинете РСЯ (шаг 3 раздела 7) и дождаться статуса
   **Активно**.

## 9. Реклама не показывается — что проверять по порядку

1. **Пользователь отказался от согласия** — по логике приложения реклама не показывается
   вообще (`ConsentManager`) и в логе будет `согласие не получено`. Это нормальное поведение,
   а не баг: показывать рекламу без согласия нельзя.
2. **Приложение в РСЯ ещё не «Активно»** — показы будут тестовыми. Проверьте статус
   в кабинете: Тестовый режим / На модерации → ждём.
3. **Не дождались загрузки** — баннер и межстраничная грузятся асинхронно; между открытием
   экрана и первым показом проходит несколько секунд. Смотрите `ConverterAds` в логе.
4. **Реклама отключена наградами** — после просмотра rewarded-ролика реклама скрывается
   на 30 минут (`ADS_REWARDED_NO_ADS_MINUTES`). Проверьте в настройках.
5. **Блокировщик рекламы или VPN на устройстве** — РСЯ может не отдавать объявления.
   Проверьте на чистом устройстве.
6. **Лимиты показа** — межстраничная по правилам показывается не раньше 3-й конвертации
   и не чаще раза в 120 секунд. Это заложено в `AdPolicy`, а не ошибка.
7. **Приложение в статусе «Остановлено»** в РСЯ — на странице приложения есть кнопка
   **Остановить**; если её нажимали, включите показы обратно: Действия → Включить показы.

## 10. Чек-лист перед загрузкой APK

- [ ] `ads.testMode=false` и три ID `R-M-20230616-2` / `-4` / `-7` в `gradle.properties` (уже так)
- [ ] плейсхолдеров не осталось: `findstr /s /n /c:"ВАШ_" /c:"demo-" app\src\main\java\*.kt gradle.properties docs\app-ads.txt`
- [ ] `Config.kt`: почта, ссылка на политику, ссылка на приложение, домен
- [ ] политика конфиденциальности открывается по ссылке из `Config.PRIVACY_POLICY_URL`
- [ ] `app-ads.txt` доступен по адресу домена, publisher ID настоящий
- [ ] `gradlew.bat testDebugUnitTest` — зелёный
- [ ] `apksigner verify --print-certs` показывает подпись ключа подписи приложения
- [ ] `versionCode` больше, чем у предыдущей загрузки в этот магазин
- [ ] в APK нет инструментов, помеченных «Скоро», в работе — только то, что реализовано
- [ ] проверено на живом устройстве: онбординг → согласие → конвертация → баннер → история
